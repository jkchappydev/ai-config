Next.js 프로젝트를 생성하고 GitHub에 업로드한다.

전달된 인자: `$ARGUMENTS`

## 1. 프로젝트 설정

전달받은 인자를 기준으로 프로젝트를 생성한다.

- 프로젝트명: 첫 번째 인자를 사용하고, 없으면 현재 디렉터리에 생성한다.
- `--private`: GitHub 저장소를 비공개로 생성한다. 기본값은 public이다.
- `--no-push`: GitHub 업로드 없이 로컬 프로젝트 생성과 검증까지만 진행한다.

이 커맨드는 Next.js 프로젝트만 생성한다. 다른 기술 스택을 요청받으면 해당 스택의 생성 커맨드를 사용한다.

## 2. 기존 파일 확인

프로젝트를 생성할 디렉터리를 먼저 확인한다.

- 기존 파일이나 Git 저장소가 있는지 확인한다.
- 이미 파일이 있다면 임의로 덮어쓰지 않고 사용자에게 확인한다.
- 기존 프로젝트인 경우 필요한 부분만 추가하거나 수정한다.

## 3. 버전 확인

프로젝트 생성 전에 사용할 버전을 확인한다.

- Context7에서 Next.js 공식 설정 방법과 최신 문서를 확인한다.
- `npm view next version`으로 최신 안정 버전을 확인한다.
- Node.js는 Next.js와 호환되는 LTS 버전을 사용한다.
- prerelease와 canary 버전은 사용하지 않는다.
- 현재 설치된 개발 환경과의 호환성도 확인한다.

버전이나 설정 정보를 확인하지 못했다면 해당 내용을 알려준다.

## 4. 프로젝트 생성

공식 생성 도구인 `create-next-app`을 사용한다.

- TypeScript, ESLint, App Router를 사용한다.
- 패키지 매니저는 npm을 사용한다.
- 의존성 잠금 파일을 포함한다.

생성 후 구조는 아래와 같다.

```text
프로젝트명/
├── src/
├── public/
├── package.json
├── tsconfig.json
├── Makefile
├── README.md
├── AGENTS.md
├── CLAUDE.md
└── .gitignore
```

## 5. 기본 파일 작성

프로젝트에 필요한 기본 파일을 작성한다.

- `README.md`: 프로젝트 구성, 사용한 버전, 설치 및 실행 방법
- `AGENTS.md`: 프로젝트 개발 지침
- `CLAUDE.md`: `@AGENTS.md` 한 줄로 작성
- `Makefile`: `make setup`, `make dev`, `make verify` 명령 제공
- `.gitignore`: `node_modules/`, `.next/`, `out/`, 환경변수 파일 등 제외

문서는 한국어로 작성한다.

## 6. 백엔드 연결 설정

기본 파일 작성이 끝나면 별도 백엔드에 연결할지 사용자에게 확인한다.

- 사용자가 연결을 요청하지 않으면 이 단계를 건너뛰고 독립 앱으로 둔다.
- 연결하는 경우 백엔드의 개발 환경 주소를 사용자에게 확인한다.
- 백엔드 프로젝트는 이 커맨드에서 생성하지 않는다.

연결하는 경우 아래를 구성한다.

- API 기본 주소를 환경변수로 분리하고, 예시 값을 담은 템플릿 파일을 함께 둔다.
- 개발 환경에서 `/api` 요청을 백엔드로 전달하도록 `next.config`의 `rewrites`를 설정한다.
- 실제 환경변수 파일은 `.gitignore`에 포함하고 템플릿 파일만 저장소에 올린다.
- 백엔드 상태를 호출해 연결을 확인하는 화면을 한 개 추가한다.

## 7. 프로젝트 검증

프로젝트 생성이 끝나면 실제로 설치, 검사, 빌드를 진행한다.

```sh
make setup && make verify
```

- 의존성 설치 확인
- 정적 검사 및 타입 검사
- 프로덕션 빌드

백엔드 연결을 구성한 경우 개발 서버를 기동해 연결 확인 화면이 정상 동작하는지 확인하고, 확인이 끝나면 프로세스를 종료한다. 백엔드가 아직 실행 중이 아니라면 사용자에게 기동을 요청하고, 확인하지 못한 항목은 결과에 함께 안내한다.

오류가 발생하면 가능한 범위에서 수정하고 다시 검증한다. 해결되지 않은 오류나 실행하지 못한 항목은 결과에 함께 안내한다.

## 8. GitHub 푸시

검증이 끝나면 아래 스크립트를 실행한다.

```sh
bash ~/.claude/scripts/gh-push.sh -m "초기 프로젝트 구성"
```

- `--private` 옵션이 전달되었다면 스크립트에도 함께 전달한다.
- `--no-push` 옵션이 있다면 GitHub 업로드를 진행하지 않는다.
- Git 초기화, 커밋, 저장소 생성 및 푸시는 스크립트에서 처리한다.
- 기본 브랜치는 `main`으로 설정한다.

## 9. 작업 결과 안내

작업이 끝나면 아래 내용을 간단히 알려준다.

- 생성한 프로젝트 구조
- 사용한 주요 버전
- 프로젝트 실행 방법
- 검사 및 빌드 결과
- 백엔드 연결 설정 여부와 설정한 환경변수 이름
- GitHub 저장소 URL (`--no-push`인 경우 제외)

## 주의사항

- 요청하지 않은 DB, 인증, 상태 관리 라이브러리, 배포 환경 등은 임의로 추가하지 않는다.
- 기존 파일은 사용자 확인 없이 덮어쓰지 않는다.
- 백엔드가 필요한 경우 별도 스택의 생성 커맨드를 사용하고, 이 커맨드에서 함께 생성하지 않는다.
- GitHub 업로드 중 오류가 발생하면 강제 푸시하거나 임의로 우회하지 않고 원인을 알려준다.
- 커밋 메시지는 제목 한 줄로 작성하고 공동작성자 표기는 추가하지 않는다.
