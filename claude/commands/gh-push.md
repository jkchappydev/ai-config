현재 프로젝트를 사용자의 GitHub 계정에 올린다. 전달된 인자: `$ARGUMENTS`

## 순서

1. **상태 파악** — 아래를 한 번에 확인한다.

   ```sh
   git status --short 2>&1 | head -30; echo "---"; git remote -v; echo "---"; git log --oneline -5 2>&1
   ```

2. **문서 갱신** — 전역 지침에 따라 커밋에 함께 포함한다. 스크립트를 실행하기 **전에** 끝낸다.
   - `PROGRESS.md`: 없으면 새로 만들고, 있으면 갱신한다. 구성은 `# 진행상황` + 목적 인용구, `## 완료된 작업`, `## 다음 진행 예정`. 날짜는 남기지 않는다.
   - `docs/worklog/<오늘 날짜>.md`: 오늘 파일이 없으면 만들고, 있으면 이어서 추가한다. 무엇을 했는지, 왜 그렇게 했는지, 관련 파일 경로를 적는다. 지난 날짜 파일은 건드리지 않는다.
   - 실제 프로젝트 내용을 읽고 쓴다. 템플릿 문구로 때우지 않는다.

3. **`.gitignore` 확인** — 없거나 `node_modules/`, `build/`, `dist/`, `.gradle/`가 빠져 있으면 프로젝트 스택에 맞게 먼저 보완한다. 스크립트가 빌드 산출물을 감지하면 중단하므로 여기서 처리하는 편이 빠르다.

4. **스크립트 실행** — 사용자가 준 인자를 그대로 넘긴다. 커밋 메시지는 `-m`으로 직접 정해서 넘기는 편이 좋다(프로젝트 내용에 맞는 한 줄, 제목만).

   ```sh
   bash ~/.claude/scripts/gh-push.sh $ARGUMENTS
   ```

   스크립트가 하는 일: git 초기화 → main 브랜치 정리 → 작성자를 `jkchappydev <jkchappydev@gmail.com>`으로 고정 → 커밋 → 레포 생성(기본 public) → `git push -u origin main` → GitHub 기본 브랜치를 main으로 지정.

5. **결과 보고** — 레포 URL, 커밋 메시지, 기본 브랜치, 갱신한 문서를 간결하게 알린다.

## 주의

- 스크립트는 멱등하다. 레포가 있으면 재사용하고, 변경이 없으면 push만 한다. 최초 업로드 이후에도 계속 쓸 수 있다.
- 스크립트가 중단되면 원인을 그대로 전달한다. 임의로 우회하거나 강제 푸시하지 않는다.
- 커밋 메시지는 제목 한 줄. 공동작성자 표기는 넣지 않는다.
- 이미 열려 있는 PR이나 관련 미병합 브랜치가 보이면 진행 전에 사용자에게 한 번 확인한다.
