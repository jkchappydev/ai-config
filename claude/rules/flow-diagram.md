# 흐름 그림 작성 규칙

사용자가 시스템이나 API의 동작 흐름을 그림으로 요청하면 아래 규칙을 따른다.

## 1. 기본 원칙

- 실제 코드를 확인하고 동작 흐름을 정확하게 표현한다.
- 처음 보는 사람도 그림만 보고 전체 흐름을 이해할 수 있도록 작성한다.
- **상자**: 서비스의 역할과 내부에서 처리하는 작업
- **상자 아래**: 해당 서비스에서 읽거나 비교하거나 변경하는 값
- **화살표 아래**: 서비스 간 요청 목적, 전달하는 값과 처리 흐름
- 하나의 서비스는 하나의 상자로 표현하고, 불필요한 단계는 생략한다.
- 결과물은 그림 한 장으로 작성하며 별도의 설명이나 범례는 추가하지 않는다.

## 2. 디자인

`~/.claude/skills/hallmark`의 Cobalt 테마(`modern-minimal`)를 사용한다.

상세 기준: `references/themes/cobalt.md`

- 라이트 테마로 고정하고, 색상은 OKLCH 토큰을 사용한다.
- 배경은 차가운 흰색, 상자는 얇은 테두리와 10px 둥근 모서리를 사용한다.
- 제목은 Space Grotesk, 본문은 Inter, 코드와 키 이름은 JetBrains Mono를 사용한다.
- 강조 색상은 코발트 하나만 사용하고, 핵심 서비스 상자에만 강조 테두리를 적용한다.
- 화살표는 1.5px 실선, 실패 흐름은 빨간 점선으로 표시한다.
- 그림자, 그라데이션, 장식용 배경, 불필요한 강조 효과는 사용하지 않는다.
- 전체적으로 여백이 충분한 깔끔한 디자인을 유지한다.

## 3. 그림 구성

기본 흐름은 왼쪽에서 오른쪽으로 배치한다.

서비스 간 호출이 여러 번 발생하거나 게이트웨이를 거치는 경우에는 흐름에 맞게 세로 또는 지그재그로 배치한다.

- 시작점은 실제 요청이나 작업이 시작되는 지점으로 표시한다.
- API 요청인 경우 HTTP 메서드, 경로, 사용자의 행동을 작성한다.
- 각 서비스 상자에는 서비스명과 주요 역할을 작성한다.
- 관련 클래스명은 필요한 경우 상자 하단에 작게 표시하며, 실제 실행 순서대로 작성한다.
- 설정 파일명과 환경변수 키 이름은 실제 코드와 동일하게 사용한다.
- 상자 아래 설명과 화살표 설명은 각각 두 줄 이내로 작성한다.
- 설명이 연결선이나 다른 상자와 겹치지 않도록 충분한 간격을 둔다.
- 사용자가 원하는 배치를 지정한 경우 해당 배치를 우선한다.

## 4. 상자와 화살표 설명

### 상자 아래

해당 서비스 내부에서 실제로 처리하는 작업을 작성한다.

- 어떤 데이터를 읽고 처리하는지 명확하게 작성한다.
- 값의 검증, 비교, 변경 등이 있다면 해당 내용을 표시한다.
- 설정 파일이나 환경변수를 사용하는 경우 실제 이름을 작성한다.
- 처리 결과는 필요한 경우에만 간단히 작성한다.
- 서비스 간 데이터 전달 내용은 화살표 설명에 작성한다.

### 화살표 아래

서비스 간 전달하는 값과 요청 목적을 작성한다.

- 어떤 데이터를 어디로 전달하는지 명확하게 작성한다.
- API 호출이라면 호출 목적과 대상 서비스를 표시한다.
- 요청 헤더나 파라미터가 중요한 경우 해당 내용을 함께 표시한다.
- 필요한 경우 화살표에 단계 번호를 표시한다.
- 헤더 예시는 실제 값이 아닌 가상의 값으로 작성하며, 필요한 항목만 표시한다.
- 상자 아래 설명과 화살표 설명에 같은 내용을 반복하지 않는다.

## 5. 성공 및 실패 흐름

- 검증 과정이 있다면 성공과 실패를 구분한다.
- 성공은 실선, 실패는 빨간 점선으로 표현한다.
- 실패 흐름에는 실패 원인과 실제 반환 결과를 표시한다.
- 검증 이후 처리와 최종 응답도 실제 코드 흐름에 맞게 연결한다.
- 서비스 내부에서 끝나는 작업은 별도 상자를 만들지 않는다.
- 응답이 돌아가는 경로도 표시하고, 최종적으로 어떤 결과가 반환되는지 작성한다.

## 6. 가독성

- 그림 폭은 약 1500px을 기준으로 하되 내용에 맞게 조정한다.
- 제목 22px, 상자 제목 17px, 본문 14px, 보조 설명 11~13px 정도로 작성한다.
- 상자 사이와 설명 영역에 충분한 여백을 둔다.
- 환경변수, 클래스명, 헤더 등 코드 관련 내용은 고정폭 글꼴을 사용한다.
- 중요한 값과 결과만 강조하고, 불필요한 굵은 글씨는 사용하지 않는다.
- 글자가 작아지거나 연결선이 복잡해지지 않도록 배치를 조정한다.

## 7. 주의사항

- 실제 토큰, 비밀번호 등 민감한 값은 표시하지 않는다.
- 설명과 흐름은 반드시 실제 코드와 일치해야 한다.
- 관련 없는 서비스나 기능은 임의로 추가하지 않는다.
- 결과물은 HTML 인라인 SVG 형태의 Artifact로 작성한다.
- 별도 요청이 없다면 그림 외의 설명은 추가하지 않는다.
